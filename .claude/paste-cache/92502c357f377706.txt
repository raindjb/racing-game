## 关键架构模式

### 1. Type-State Pattern
- `agent/type_state.rs`: Agent 生命周期编译时验证
- `agent/task_builder_typestate.rs`: TaskBuilder 编译时验证
- 零运行时开销，状态转换在编译期检查

### 2. Channel-Based Orchestration
- 使用 `tokio::sync::mpsc` 和 `async-channel`
- `coordination/mod.rs`: Agent 间消息传递
- 避免 `Arc<Mutex>`，用 actor 模型替代

### 3. Actor Model
- 每个 agent 是独立 actor
- 通过 channel 接收消息
- `agent/pool.rs`: Agent 池管理

### 4. Error Handling
- `error.rs`: `CCSwarmError` 使用 struct variants（不是 tuple）
- 所有错误带上下文：`Agent { agent_id, message, source }`
- `utils/error_recovery.rs`: 错误恢复策略

### 5. Hook System
- `hooks/mod.rs`: PreToolUse/PostToolUse 模式
- `hooks/registry.rs`: 优先级注册表
- `hooks/builtin.rs`: 内置日志和安全验证 hook

## 已知限制

1. **`start` 命令退出立即**: 协调循环未实现，启动后不持续运行
2. **ParallelExecutor 未接通**: 结构存在但没接到 orchestrator
3. **ACP WebSocket 未实现**: 只有 CLI wrapper
4. **ai-session MessageBus 未集成**: agent 间无法通过 ai-session 通信
5. **无 IPC**: 命令间隔离，每个命令独立运行
6. **不支持 Windows**: 用了 Unix PTY（nix crate），需 WSL
